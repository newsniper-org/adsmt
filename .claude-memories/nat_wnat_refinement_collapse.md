**User proposal (2026-06-27):** treat `Nat` as `Int > 0` and `WNat` as `Int ≥ 0` (i.e. `Nat = {x:Int | x≥1}` since **0∉Nat**, `WNat = {x:Int | x≥0}`). This is the **refinement-type view** and the cleanest realisation of #338 ([[lukb-type-relation-utilization]]) + the `Reduces` spine ([[numberlike-family-design]]) for the integer carriers, with **encode = the identity inclusion ℕ↪ℤ** (not an abstract function). Closes the gap where `nat2int(x)` reaches `LinArith` as an opaque function APPLICATION (not a bare arith `Var`) so the order laws over Nat/WNat stay native-`Unknown` ([[oxiz-mbqi-rewrite]]/EngineLawProver).
