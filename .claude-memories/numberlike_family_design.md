**The `*Like` family (a "type relation" = type-class; the user's term) — final design, grounded in the EXISTING `adsmt-class` layer** (`Relation{name,params,fundeps,methods}` / `Instance{relation,types,premises,methods}` / SLD `Resolver` = "dictionaries over rank-1 HOL"). Blueprint for #339; implementation order: IntegerLike → RealLike → (G1 gate + resolver) → PartialIntegerLike → ComplexLike → (frontier) deg-n.

**FOUR relations sharing a reduction-first SPINE:**
- `Reduces(C:Type)` — fundeps `[C]→[Base,Rep]`; methods `{base:LIA|LRA|NIA|NRA|EUF, rep:Scalar|Pair(C'), encode:C→rep (TOTAL,INJECTIVE), decode, lower:Op→ReducedConstraint, domain}`. The capability every member installs.
- `IntegerLike(I)` — premise `Reduces(I, NIA-ceiling, Scalar, id, …, domain)`. Instances `Int`[⊤], `Nat`[`nat2int x ≥ 1`], `WNat`[`≥0`], Peano-data. Order=TotalDiscrete (instance metadata). lower: `{+−<≤>≥}`→LIA, `{× both-nonconst, pow}`→NIA, `{div,mod}`→EUF(partial).
- `RealLike(R)` — sibling base, `Reduces(R, NRA, Scalar, …)`. Instance `Real`(ℝ/ℚ). Order=TotalDense. **NO IntegerLike⊂RealLike class edge** — ℤ⊂ℝ is the `int2real` injection only.
- `PartialIntegerLike(E,B)` — fundeps `[E]→[B]`; **premise `IntegerLike(B)`** (◀ the HKT edge); `Reduces(E, NIA, Pair(B), split2, …)`; methods `{minpoly:MonicPoly2 B, norm}`. Instances Gaussian ℤ[i] `[c0=1,c1=0]`, Eisenstein ℤ[ω] `[c0=1,c1=1]`. Order=PartialOrd (comparisons→EUF, NEVER reduced).
- `ComplexLike(C,B)` — premise `RealLike(B)` ⊕ `IntegerLike(B)`; `Reduces(C, NRA|NIA, Pair(B), …)`; methods `{minpoly, norm, inv:Option}`. Instances ℂ=ℝ[i], etc. Order=NoOrder (`<≤>≥` REJECTED at elaboration).

**HKT is HONEST (rank-1 kernel, zero new trusted surface):** "a *Like takes a *Like" is a **value-level `Premise` EDGE the SLD Resolver discharges**, NOT a kinded parameter (Base is `Kind::Type`, first-order — verified vs adsmt-core `is_first_order()`). The only genuine higher kind (`Poly:Type→Type`) is AVOIDED — minpoly is degree-2-FIXED instance DATA `MonicPoly2 B` (two coeffs), not a `Poly`-typed term. Carrier sorts + ops are `Modality::Open` postulates; kernel only type-checks → a malformed instance can only fail to type-check.

**Reduction (verified algebra):** extension mul via `ζ² = −(c0+c1·ζ)` from monic `x²+c1·x+c0`: `(a,b)·(c,d) ↦ (ac−c0·bd, ad+bc−c1·bd)` [Gaussian (ac−bd, ad+bc); Eisenstein (ac−bd, ad+bc−bd)]. eq is CONJUNCTIVE `a=c ∧ b=d`. norm = `a²−c1·ab+c0·b²` (minpoly-derived, NOT hardcoded a²+b²).

**9 SOUNDNESS GUARDS (every one a false-unsat/false-sat trap):** G1 minpoly IRREDUCIBILITY admission gate (reducible deg-2 → zero divisors → false-unsat; decidable by discriminant, HARD-reject in `declare_instance`, z3-differential for deg-n). G2 NIA/NRA-absent ⟹ ABSTAIN Unknown (oxiz-nl2 not yet on the polite bus). G3 model Pair as PRIMITIVE tuple, not datatype-with-selectors (avoid the sel(x)/sel(C(..)) gap). G4 NoOrder REJECTS never coerces. G5 CONJUNCTIVE equality (disjunctive → false-sat). G6 RING-complete base ONLY (FORBID Nat/WNat bases — no subtraction closure). G7 div/inv Option-gated on norm≠0, never manufactured. G8 minpoly is STATIC instance data. G9 cross-sort = explicit injection.

**Four-way interlock payoff:** ONE instance's `{premise graph, lower, domain, order, minpoly}` serves type-inference (SLD resolution = the same walk), abduction (norm≠0/inv = abduction hooks), ASP (domain positivity + order metadata), SMT (Reduces.lower routing) — a single G1 gate protects all four; a new number system = a new Instance (4 fields + 2 premises), auto-available to all four engines. See [[four-way-interlock-design-intent]], [[lawful-type-relation-instances]] (goals-as-members proof-gating). First member already wired SOUND into the solver: the `IntegerLike(Peano)` arith bridge ([[lukb-type-relation-utilization]], commit `b76ab2b`).

**Open questions for impl:** (1) oxiz-nl2-on-the-bus timing (extensions are Unknown-abstaining until NIA/NRA registered in the same `polite.rs` Combination as LinArith). (2) Pair-rep: primitive tuple (new kernel/theory primitive) vs datatype+selectors (reuses but inherits the gap). (3) lukb surface syntax to DECLARE a `*Like` instance (`type-relation`/`instance` keyword + minpoly + `cite`).

**REFINEMENT (user, 2026-06-27, inspired by Rust `Eq: PartialEq`) — the `Partial` prefix is the ORDER-LAW axis, ORTHOGONAL to the extension axis.** Rust's `Eq: PartialEq` adds the *reflexivity LAW* (a==a) as a marker subtrait, no new methods. Apply to numbers as the order-law hierarchy:
- `PartialIntegerLike` = the more GENERAL superclass: integer-like ring/integral-domain with a PARTIAL order (or none) — covers ℤ, ℕ, WNat **AND** Gaussian ℤ[i], Eisenstein ℤ[ω].
- `IntegerLike : PartialIntegerLike` = the subtrait that adds the **TOTAL-ORDER LAW** (∀a,b. a≤b ∨ b≤a) — covers ℤ, ℕ, WNat only. **ℤ[i] is PartialIntegerLike but NOT IntegerLike** (no compatible total order) — exactly as `Eq` fails for float (NaN).
- This is the canonical instance of [[lawful-type-relation-instances]]: the **total-order law IS `IntegerLike`'s gating goal-member** — an instance is admitted as `IntegerLike` only if the solver discharges total-order; ℤ proves it, ℤ[i] fails → admitted as `PartialIntegerLike` only. (The general form of `Eq`'s reflexivity marker.) Likewise the field side: `ComplexLike` (no order, ℂ) is the weakest field relation; `RealLike` adds total-order over a field (ℝ, ℚ).
- This ORDER-LAW subtrait axis is ORTHOGONAL to the earlier EXTENSION axis (`Reduces` Pair(B), minpoly). ℤ[i] is BOTH (a) a degree-2 ring extension of ℤ (Pair(Int), x²+1) AND (b) a `PartialIntegerLike` (not IntegerLike). ℤ is BOTH a Scalar base AND `IntegerLike`. So the family graph has two kinds of edge: subtrait/law edges (`IntegerLike → PartialIntegerLike`, gated by a proven law) and extension/premise edges (the carrier's `Reduces` over a base `*Like`). The workflow's `PartialIntegerLike(E,B) premise IntegerLike(B)` is the EXTENSION edge; the subtrait edge `IntegerLike(I): PartialIntegerLike(I)` is this refinement.

**FURTHER REFINEMENT (user, 2026-06-27) — `ComplexIntegerLike` is a DEDICATED relation for ℤ[i]/ℤ[ω], a sibling of `IntegerLike` under `PartialIntegerLike`.** The final integer-side hierarchy is THREE relations:
- `PartialIntegerLike` — SUPERCLASS: integer-like commutative ring / integral domain, partial order (or none). Parent of both below.
  - `IntegerLike : PartialIntegerLike` — adds the TOTAL-ORDER law → ℤ, ℕ, WNat. Scalar rep, LIA/NIA.
  - `ComplexIntegerLike : PartialIntegerLike` — adds the COMPLEX-GENERATOR structure (`a+bζ`, ζ a root of an imaginary-quadratic monic minpoly, components over an `IntegerLike` base, NO total order) → **ℤ[i]** (i²+1=0), **ℤ[ω]** (ω²+ω+1=0). Pair(ℤ) rep, NIA on components.

  `IntegerLike` and `ComplexIntegerLike` are SIBLING subtraits of `PartialIntegerLike` (one adds total-order, the other the complex structure) — ℤ ∈ IntegerLike only, ℤ[i] ∈ ComplexIntegerLike only, both ∈ PartialIntegerLike. This RENAMES/RESHAPES the workflow's `PartialIntegerLike(E,B)` extension member: that member (the ℤ[i]/ℤ[ω] carrier) is now `ComplexIntegerLike`, and `PartialIntegerLike` is freed up to be the genuine partial-order superclass.

Field side mirrors it: `RealLike` (totally-ordered field, ℝ/ℚ, Scalar, LRA/NRA) and `ComplexLike` (complex field ℂ = a+bi, no order, Pair(ℝ), NRA). **KEY SYMMETRY: `ComplexIntegerLike` (over ℤ) ↔ `ComplexLike` (over ℝ)** — both are Pair-rep + minpoly extensions; they differ ONLY in the coefficient base (`IntegerLike` vs `RealLike`) and the routed theory (NIA vs NRA). So the family is 5 relations: PartialIntegerLike ⊃ {IntegerLike, ComplexIntegerLike}; RealLike; ComplexLike. (The workflow's G1–G9 guards + reduction algebra carry over unchanged; only the naming/hierarchy is sharpened.)

**ORDER AXIS FACTORED OUT + LAWFUL-BY-PROOF MECHANISM (user, 2026-06-27).** The order capability is its OWN standalone pair of relations (so each `*Like` reuses it instead of re-declaring an order), inspired by Rust `Ord: PartialOrd`:
- `PartialOrd(I)` — method `le:I→I→Bool`; **laws** (goal-members) reflexivity / antisymmetry / transitivity.
- `Ord(I) : PartialOrd(I)` — premise `PartialOrd(I)`; adds the **totality** law `∀a b. le a b ∨ le b a`, **no new method** (`le` inherited through the premise; the `Eq:PartialEq` marker shape).
- `IntegerLike(I) : PartialIntegerLike(I), Ord(I)` — premises BOTH; a pure conjunction marker, NO own methods/laws (the `le` + order laws now come via `Ord`, the ring core via `PartialIntegerLike`). ComplexIntegerLike will premise `PartialIntegerLike` but NOT `Ord` (no total order).
- Field side: `RealLike(R) : PartialOrd(R)` (FloatingPoint-like reals are only partially ordered — NaN). **CORRECTION (user): genuine mathematical Real does NOT "inherit Ord" — instead, FOR THE GENUINE REAL ONLY, an `Ord(Real)` instance is ADDITIONALLY declared** (a separate instance decl, not a RealLike premise). `ComplexLike` = no order at all.
- **`FloatingPoint(M:Nat, E:Nat)` (user) — declare FP as a DEPENDENT-TYPED datatype** parameterised by mantissa-bits M and exponent-bits E (Nat-valued type params); it is a `RealLike` carrier that is `PartialOrd`-only, never `Ord` (NaN ≠ NaN, no total order). [Later slice.]

This is the canonical realisation of [[lawful-type-relation-instances]]: laws are **goal-members of a relation** and an `Ord` instance is admitted **only if the solver discharges totality** for its `le` — a non-total carrier (FloatingPoint) is build-REJECTED on that gate and stays `PartialOrd` only.
