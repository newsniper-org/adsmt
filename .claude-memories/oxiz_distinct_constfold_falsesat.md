**OxiZ constant-folding FALSE_SAT (#315) — FIXED 2026-06-25 (OxiZ `3d8f77d`, `0.2.4-redesign`, UNPUSHED).** A z3/cvc5 differential found a pre-existing soundness bug: atoms whose args constant-fold to a definite (in)equality were reported **sat**. Two root causes, both in the term simplifier `oxiz-solver/src/simplify.rs`:

1. **`distinct` was not desugared.** The encoder (`encode.rs` `TermKind::Distinct`) gave it a bespoke result-variable biconditional that, for arith-equal but non-SYNTACTICALLY-equal terms, behaved like an EUF **syntactic** disequality — so `(distinct (* 0 x) 0)` = `0≠0` was **sat**, while the explicit `(not (= (* 0 x) 0))` was correctly unsat. FIX: a `Simplifier` `TermKind::Distinct` arm desugars to the definitional pairwise `(not (= aᵢ aⱼ))` (recursively simplified). For uninterpreted sorts that IS the EUF disequality → SAT cases (`(distinct x y)`, QF_UF) unchanged. **Future distinct changes go through the simplifier desugar, not the encoder.**
2. **No arithmetic constant folding.** `(* 0 x x)`, `(+ 2 (- 2) p)`, nested `(+ 0 0 0)` were never reduced (simplifier's default arm `_ => term` doesn't even recurse), so a *disequality* over them missed the contradiction (the `=`/`<` paths evaluate the poly, but `≠` did not). FIX: simplifier arms for `Mul` (`0·_=0` + combine integer constant factors), `Add` (recurse + combine integer constant addends + drop zeros), `Sub`, `Neg`. Sound (value-preserving).

VALIDATION: z3/cvc5 differential **FALSE_UNSAT=0 across 3500 random QF_NIA** (the broad simplifier change adds no false unsat); every const-fold distinct/arith bug case now matches z3; **1658** oxiz-solver/oxiz-theories lib tests green; Int+Real+UF spot-checks; regression `test_simplify_arith_fold_and_distinct`. Found+fixed during the multi-paradigm fdlcg work (the same z3-differential harness `nia_diff.py` that validated the fd_core add-on surfaced it; baseline-confirmed pre-existing, fd-unreachable). See [[multi-paradigm-hybridization]].

**ZERO-ABSORBING follow-up (OxiZ `0e96573`)** — user insight: in ANY ring (NIA/NRA/LIA/LRA…ℂ/ℍ/𝕆), a product with any zero factor (constant OR a variable whose VALUE is 0) is trivially 0. The static-constant case is the const-fold above; this closes the RUNTIME case. Differential found `x=0 ∧ x²≠0` (=`0≠0` by absorption) reported sat (likewise `0≤x≤0 ∧ x²≠0`, `x=0 ∧ xy≠0`). **fd_core ALREADY embodies absorption** (its `riv_mul` gives `[0,0]·_=[0,0]`); the disequality just never reached it. Two gaps in `oxiz-theories/src/nlsat.rs`: (1) `extract_poly_atoms` dropped negated comparisons → added `Not(cmp)` (polarity-flip → `¬(=)` becomes a `≠0` Ne atom) + `Distinct` (pairwise `≠0`); (2) `term_is_nonlinear` didn't recurse through `Not`/`Distinct`/`Or`/`Implies`/`Xor`/`Ite` → `(not (= x² 0))` looked linear → `has_nl=false` → dispatch returned BEFORE the fd_core consult → CDCL(T) mishandled it. Now all zero-absorbing disequalities decided (z3-matched); FALSE_UNSAT=0 across 3000; regression `fd_core_addon_zero_absorbing_disequality_unsat`. LESSON: a sound add-on engine is only as good as what reaches it — audit BOTH the routing gate (`term_is_nonlinear`/`has_nl`) AND the atom-extraction (`extract_poly_atoms` dropping negations) when a known-good engine "doesn't fire."

**RESIDUAL (still open) = [[#289]] OxiZ LIA/nonlinear integer-feasibility FALSE_SAT** — a SEPARATE class the differential still shows (~5-10/300): genuine integer-infeasibility the solver misses, e.g. deriving `x=0` from `x(1+x)=0` then violating a nonlinear `x²≠0`, or a linear system with only a rational (non-integer) solution. NOT constant-folding; regression-risky (touches the arith/LIA solver core), deferred. The differential's FALSE_UNSAT=0 holds throughout — only FALSE_SAT (completeness-of-refutation) remains, all in this class.
