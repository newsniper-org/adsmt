Design doc: `external/oxiz/docs/design/CCFV_UNIFIED_INSTANTIATION.md` (sketch v1).

**Core thesis:** the three current strategies (trigger e-matching `oxiz-mbqi/src/trigger.rs`, CDQI `cdqi.rs`, enumeration `engine.rs`) each duplicate *enumerate → unify → gate*; CCFV makes them **parameterizations** of "find all σ with E ⊨ Cσ" — triggers = `C=⋀pᵢ≃yᵢ`, conflict = `C=¬ψ` (ALL conflicts), MBQI/model-completion = `C=¬ψ` against total model `E_TOT`. The `emit`/`instantiate` soundness gate is UNCHANGED → never-conclude-unsat preserved (CCFV is a smarter source behind the same wall). EUF already has the `E^cc` index (`sig_table`, `function_application_entries`, `fingerprint_table`); current "e-matching" is congruence-BLIND syntactic match over `GroundIndex.by_head` — that's the gap + why discard can't run.
