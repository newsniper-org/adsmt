# 위임 신뢰 구조 재설계 — 문제 제기와 단계 계획

2026-08-30. 사용자 지시: *"위임 그 자체에 대한 의존도를 낮출 필요가 있어
보인다."* 이 문서는 그 판단을 뒷받침하는 측정치를 모으고, 실행 가능한 단계로
쪼갠다. **아직 결정된 계획이 아니라 결정을 받기 위한 문서다.**

## 1. 현재 자세, 한 문장으로

adsmt는 위임 엔진의 `sat`을 불신하고 `unsat`을 신뢰한다
(`adsmt-delegate/src/oxiz.rs` 모듈 doc). 그리고 209행 코퍼스의 **verified 171행
전부가 그 신뢰받은 `unsat`에 얹혀 있다.**

## 2. 그 자세가 방향을 거꾸로 잡고 있다

두 방향의 비용이 대칭이 아니다.

| 위임 엔진의 오류 | adsmt에 미치는 영향 |
|---|---|
| false-**SAT** (모델을 지어냄) | **없음.** `sat`은 애초에 신뢰하지 않으므로 "위임 없음"으로 떨어진다 |
| false-**UNSAT** (거짓 반박) | **치명.** 그대로 `DefiniteUnsat`이 되어 검증 도장이 찍힌다 |

즉 우리가 방어하고 있는 방향은 원래 해롭지 않은 쪽이고, 실제로 해로운 쪽은
무방비다.

## 3. 이번 세션의 실측 — 빈도가 낮지 않다

2026-08 한 세션에서 위임 엔진에서 발견·확정된 소인성 결함:

| 번호 | 방향 | 상태 |
|---|---|---|
| #426 발화-불충분 트리거 면제 | false-SAT | CLOSED |
| #427 `ALL` 로직 정수성 미도달 | false-SAT | CLOSED |
| #428 clause-id-recycle + eq-trichotomy | false-SAT | CLOSED |
| #429 타 이론 Int 항 정수성 미도달 | false-SAT | CLOSED |
| **#430 EUF→arith 함의** | **false-UNSAT** | **OPEN (미랜딩)** |
| #431 배치 시그니처 게시 | false-SAT | CLOSED |
| #431b 맨 push/pop이 레벨0 모순 폐기 | false-SAT | CLOSED |
| **#432 `define-fun` 형식인자 소실** | **false-UNSAT** | CLOSED |
| #433 Bool EUF 미완성 ×2 + 비볼록 분할 | false-SAT | CLOSED |
| #434 arrangement 미이행 | false-SAT | OPEN |
| **#435 `(check-sat)` 후 절 추가** | **false-UNSAT** | **OPEN** |

**false-UNSAT 3건 중 2건이 지금 열려 있다.** #430은 비용 때문에 의도적으로
미랜딩이고, #435는 원인 미규명이다. 두 건 다 "위임 `unsat`을 무조건 신뢰"하는
현재 자세에서는 그대로 거짓 검증이 된다.

그리고 이 목록은 **우리가 찾은 것**이지 **있는 것 전부**가 아니다. 대부분은
랜덤 differential이 찾았고, differential은 우리가 겨냥한 모양만 본다.

## 4. 방향 — 위임을 *권고*로 강등하고 신뢰는 *검사*로 얻는다

핵심 전환: **위임 `unsat`은 그 자체로 `DefiniteUnsat`이 아니다.**
`SatLevel` 격자가 이미 이걸 표현할 수 있다 — 위임 결과는 기본
`PossiblyUnsat`(= `unknown`으로 붕괴)이고, 다음 중 하나를 통과해야
`DefiniteUnsat`으로 올라간다:

- **A. 인증서 검사** — 위임 엔진이 증명을 내고 adsmt가 직접 검사한다.
- **B. 교차 확인** — 독립 백엔드가 같은 `unsat`을 낸다.
- **C. 네이티브 재현** — adsmt 자체 엔진이 같은 결론에 도달한다.

이 셋은 배타적이지 않고 비용/커버리지가 다르다.

## 5. 단계

### S1 — 계측 먼저 — **완료 2026-08-30. 답이 나왔다.**

`.lukb → adsmt-ir-lukb::elaborate → 커널 → adsmt-ir-lower → adsmt-engine`,
위임 없음. 드라이버 `adsmt-ir-lukb/examples/lukb_solve.rs`, 전량
`corpus-triage/2026-08-30-native-only-lukb-verdicts.tsv`.

|  | 네이티브 `unsat` | 네이티브 `unknown` |
|---|---|---|
| 위임 verified (171) | **90** | 81 |
| 위임 미verified (38) | **0** | 38 |

**위임 의존도는 171행이 아니라 81행이다.** 원장의 53%는 이미 네이티브로
닫히고 있었고, 그 사실을 아무도 몰랐다.

그리고 **네이티브가 위임을 앞서는 행이 0개** — 네이티브 판정 집합이 위임
판정 집합의 진부분집합이므로, 이 스윕은 네이티브 false-UNSAT 후보를 하나도
드러내지 않는다. (증명은 아니다. 위임 집합 자체가 핀된 z3 fixture로 교차
확인된 것이라는 점이 이 신호의 근거다.)

209행 전부가 **파싱 209/209, elaborate 209/209** 이므로, 119개의 unknown은
전부 엔진 abstain이지 면(face)이나 lowering의 구멍이 아니다.

**이 숫자가 §6의 "정직한 비용"을 다시 쓴다.** 위임 `unsat`을
`PossiblyUnsat`으로 강등해도 원장은 0으로 무너지지 않는다 — 즉시 **90**에서
시작하고, 나머지 81행이 인증서 또는 교차 확인을 필요로 한다. S2/S3의 작업량
견적이 그만큼 줄어든다.

### S2 — 인증서 검사 (가장 큰 레버)

업스트림 OxiZ가 **온라인 LRAT 생성 + 순수 Rust LRAT 검사기**를 이미 실었다
(v0.3.2 도입, 현재 태그 v0.3.3, `0.3.4` 브랜치 진행 중). 우리 포크에는
없었다 — 양방향 포팅의 최우선 항목.

- 접지 부분은 오늘 당장 검사 가능하다.
- 수량화 부분은 인스턴스 목록이 필요한데, **adsmt는 이미 그걸 갖고 있다**
  (`clean_instances`). 위임이 낸 인스턴스 집합 + 접지 LRAT이면 전체가 닫힌다.
- 이 경로가 있었다면 #430·#432·#435 전부 **경계에서** 걸렸다. differential이
  우연히 찾을 때까지 기다릴 일이 아니었다.

#### S2는 한 덩어리가 아니다 — 이식 난이도가 정반대인 두 조각이다

업스트림 파일을 실제로 열어보고 갈라졌다 (2026-08-31):

| 조각 | 업스트림 위치 | 규모 | 우리 쪽 이식 난이도 |
|---|---|---|---|
| **검사기** | `oxiz-proof/src/lrat_check.rs` | 494줄 + 테스트 223줄 | **낮음 — `std`만 의존.** 파일 복사 |
| **생성기** | `oxiz-sat/src/solver/lrat_trace.rs` + `add_clause.rs`/`proof.rs` 훅 | 485줄 + 다수 훅 | **높음 — §4 SAT-코어 재설계로 우리가 갈아엎은 바로 그 코드.** 복사가 아니라 머지 |

그래서 순서를 이렇게 잡는다:

**S2a (완료) — 검사기 이식.** `lrat_check.rs`를 업스트림 v0.3.3에서 **바이트
동일**로 가져왔다. 로컬 변종을 만들지 않은 것은 의도다: 다음 업스트림 동기화
때 이 파일이 무충돌이 되고, 증명 검사기야말로 로컬 포크를 두면 안 되는 물건이다.

정직하게: **이것만으로는 아직 원장이 1행도 안 움직인다.** 검사할 증명을 내는
생산자가 우리 쪽에 없기 때문이다. 이 단계가 사는 것은 (a) 외부 LRAT 생산자
(cadical/kissat `--lrat`)의 증명을 검사할 수 있게 됐다는 것과 (b) S2b가 붙는
순간 검사 측이 이미 준비돼 있다는 것이다.

**S2b (범위 산정 완료, 미착수) — 생성기. 유계 이식이 아니다.**

2026-08-31에 범위를 재고 적대적으로 검토했다. 결과가 낙관을 지웠다.

*먼저 고쳐서 랜딩한 것*: 우리 `LratWriter`가 힌트가 빈 추가 줄에 **종결자
`0`을 안 썼다.** 그래서 우리 기록기의 출력을 우리 검사기가 거부했다
("line 1: addition line missing hint terminator 0"). `add_original_clause`는
항상 빈 힌트를 넘기므로 **원본 절 줄이 전부 파싱 불가**였다. 업스트림이
v0.3.2/v0.3.3에서 같은 버그를 이미 고쳤고 주석이 우리 구현을 그대로
서술한다. 백포트했고, `reserve_original_id`도 함께 가져왔으며, 왕복
테스트(기록기 → 검사기)를 붙였다. **아무도 못 잡은 이유는 두 반쪽을 서로
붙여 돌려본 적이 없어서다** — 각자 자기가 생각하는 형식에 대해서만 테스트됐다.

*그리고 유계가 아닌 이유*:

| 차단 요인 | 위치 | 성격 |
|---|---|---|
| **힌트 체인 생성이 아예 없다** | `conflict.rs`의 네 `Reason::Propagation` 독출부가 id를 쓰고 버린다 | 버그가 아니라 **없는 코드**. 이식의 본체 |
| **입력 단위절이 절로 물질화되지 않는다** | `mod.rs:806-853` — trail에 `Reason::Decision`으로 얹고 `ClauseId` 없이 반환 | 단위절을 citing하는 힌트가 **표현 불가** |
| **학습 단위절도 레벨0에 `Reason::Decision`으로 얹힌다** | `mod.rs:1057`, `learn.rs:46` | 아래 실측의 원인 |
| **이론 경로는 증명 로깅에서 의도적으로 제외** | `learn.rs:169-173`의 명시적 NOTE | **adsmt가 실제로 위임하는 경로가 바로 이것** |
| 절 id 재활용 | `clause.rs:405/504-516/589` | LRAT id를 `ClauseId`로 쓰지 않으면 회피 가능 |
| in-place 강화가 id를 유지한 채 리터럴 변경 | `learn.rs:394` | free list와 **무관한** 두 번째 id-불안정 경로 |

*"레벨0 반박만" 최소 슬라이스는 실측으로 죽었다.* 랜덤 3-SAT 200시드
(단위절·항진절 없는 입력), UNSAT 193건:

```
레벨0 `Reason::Decision` 리터럴을 가진 것        193 / 193
레벨0 학습절 antecedent을 가진 것                 75 / 193
원본 + 입력 단위절만으로 재구성 가능한 것            0 / 193
```

레벨0 종료(`mod.rs:1024`)가 CDCL 루프 **안**이라 학습 이후에만 도달하기
때문이다. 그러니 그 슬라이스는 실제 입력에서 증명을 하나도 못 낸다.

*그리고 내가 틀렸던 것*: "`#428`의 `ClauseIndexScrub` 불변식이 id 맵을
컴파일러 수준에서 지켜준다"고 적었는데, **`Solver::reset`이 그 보장을
우회한다**(`mod.rs:1941-1942`가 `ClauseDatabase`를 통째로 교체 — `remove` 0회,
scrub 0회). sink는 watches/binary_graph 둘만 덮고 **trail reasons는 밖**이다.
`(reset)`/`(reset-assertions)`에서 도달한다. 별도 티켓으로 등록했다.

*결론*: S2b는 별도 슬라이스가 아니라 **선행 조건이 딸린 프로젝트**다. 순서는
(1) 등록한 소인성 후보들부터(특히 `check_subsumption`의 locked 검사 누락),
(2) 힌트 체인 생성, (3) 접지 SAT 코어 한정 증명. 그리고 (3)이 끝나도
**위임 경로의 이론 렘마는 LRAT로 인증되지 않는다** — 그건 RUP 체인이 아니라
Alethe/LFSC 계열의 별도 정당화 층이 필요하다. S2의 원래 문장("접지 부분은
오늘 당장 검사 가능하다")은 그 점에서 낙관적이었다.

### S3 — 다중 백엔드 (태스크 #46, 이미 계획됨)

in-process z3를 2번째 백엔드로 붙이고 `SatLevel::meet`으로 조정한다.
**불일치는 조용히 `Unknown`으로 만들지 말고 크게 표면화**한다 — 불일치는
둘 중 하나가 소인성 결함이라는 뜻이고, 그건 원장 한 줄보다 중요한 정보다.
S2가 있으면 S3는 인증서를 못 내는 조각(수량화, 비선형)의 보완재가 된다.

### S4 — 네이티브 지분 늘리기

S1이 준 분모 위에서, 네이티브가 가져갈 수 있는 조각을 늘린다. 이건 가장 느린
레버지만 유일하게 의존도를 **구조적으로** 낮춘다.

## 6. 정직한 비용

S2/S3를 켜면 **원장 171이 일시적으로 내려간다.** 인증서를 못 내거나 교차
확인이 안 되는 행은 `PossiblyUnsat` → `unknown`이 된다. 그건 회귀가 아니라
**지금까지 세던 방식이 낙관적이었다는 사실의 노출**이다. 그 숫자를
verus-fork와 공유하는 상호 정본으로 쓰고 있으므로, 전환한다면 그쪽과
동시에 정의를 바꿔야 한다.

## 7. 결정이 필요한 것

1. S1을 지금 착수할지 (저비용, 다른 모든 판단의 입력).
2. S2의 LRAT 포팅을 업스트림 양방향 포팅의 최우선으로 올릴지.
3. 원장 정의를 "위임 `unsat` = verified"에서 "검사된 `unsat` = verified"로
   바꿀지, 바꾼다면 verus-fork와 언제 맞출지.
