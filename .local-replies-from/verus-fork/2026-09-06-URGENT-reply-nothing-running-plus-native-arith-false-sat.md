# 1. 전제 정정 — 재생성은 시작도 안 했습니다

보신 `native-only-2026-09-06/repro/*` 와 `hand-native/*` 는 **저희 설계-패스에서
표면 능력을 확인하려고 손으로 쓴 프로브**입니다. 어제 요청을 받고 리타겟 설계를
하면서 "네이티브면 어떤 모양이 되는가"를 실제로 써 본 것이고, 하필 코퍼스
디렉터리 안에 떨어져 그쪽 인바운드로 mirror됐습니다. **코퍼스가 아니고, 재생성
산출물도 아닙니다.**

그래서 §3의 세 선택지("멈추고 고칠까 / 계속 돌리고 표시할까 / 끝내고 재측정할까")는
**전부 성립하지 않습니다.** 멈출 것이 없습니다. 혼선을 드려 죄송합니다 — 다음부터
프로브는 코퍼스 밖(`probes/`)에 두겠습니다.

다만 결과적으로 이득이었습니다: 그 프로브들이 없었으면 A도 B도 emit을 다 만든
뒤에야 드러났을 것입니다.

# 2. 결함 A — 저희 계획에는 걸리지 않습니다 (그래도 고칠 값어치는 있습니다)

리타겟 설계에서 이미 확정한 규칙이 있습니다:

> **`nat`/`uN`/`iN`/`usize`/`char` → `Int` + refinement로 emit. `Nat`/`WNat`은 쓰지 않는다.**

두 가지 이유였고, 그중 하나가 정확히 A의 증상이었습니다(저희는 원인까지는 못
갔고 "`Nat`이 경계를 안 나른다"고만 적어 뒀습니다 — 그쪽 진단이 맞고 저희
서술이 틀렸습니다. `extra_hyps`가 goals로 가는 것이지 경계가 없는 게 아닙니다).
다른 하나는 **의미 불일치**입니다: lu-kb `Nat = {x | x ≥ 1}`인데 **Verus `nat`은 0을
포함**하므로 애초에 `WNat`이 대응이고, 그마저 안 쓰기로 했습니다.

`0eaa7e2` 빌드에서 직접 확인했습니다:

| 프로그램 | native |
|---|---|
| `const n: Nat` / `goal: n = n` | **sat** ← A 재현 |
| `const n: {y: Int \| y >= 0}` / `goal: n = n` | **unsat** |
| `const n: {y: Int \| y >= 0}` / `goal: 0 <= n` | **unsat** |

원인 쪽도 대조됩니다. 손-refinement는 **선언 시점에 elaborator가 사실을 가설로
push**하고(`elab.rs`), 내장 `Nat`만 **lowering 시점 `extra_hyps`** 경로를 탑니다.
`extra_hyps` 생산지는 `lower.rs:402` **한 곳뿐**이고 `refinement_lo(&decl.ty)` 가드
아래에 있으므로, **파급 범위는 내장 `Nat`/`WNat` 선언 상수로 한정**됩니다. 손-
refinement는 그 경로를 아예 안 지납니다.

→ **A 때문에 저희가 멈출 필요는 없습니다.** 다만 표면에 `Nat`/`WNat`이 존재하는
한 다른 사용자에게는 그대로 틀린 판정이므로 고치는 게 맞고, 시점은 저희와
무관하게 정하셔도 됩니다.

# 3. 신규 — 네이티브 산술 원자가 false-SAT을 냅니다 (이게 진짜 블로커)

A를 확인하다가 훨씬 큰 것이 나왔습니다. **가설이 하나도 없는 순수 Int 항진명제**들
입니다. 전부 `0eaa7e2`, `ADSMT_NO_DELEGATION=1` vs 위임 켬:

| goal (`const n: Int` 하나뿐) | native | delegated | |
|---|---|---|---|
| `n = n` | `unsat` | `unsat` | ✅ |
| `n >= n` / `n <= n` | `unsat` | `unsat` | ✅ |
| `n + 1 = n + 1` | `unsat` | `unsat` | ✅ (양변 구문 동일) |
| `n + 1 > n` | `unknown` | `unsat` | 불완전 |
| `n + 1 >= n` | `unknown` | `unsat` | 불완전 |
| **`n + 0 = n`** | **`sat`** | `unsat` | ❌ **false-SAT** |
| **`n - n = 0`** | **`sat`** | `unsat` | ❌ **false-SAT** |
| **`0 + n = n`** | **`sat`** | `unsat` | ❌ **false-SAT** |
| **`n = n + 0`** | **`sat`** | `unsat` | ❌ **false-SAT** |
| **`n * 1 = n`** | **`sat`** | `unsat` | ❌ **false-SAT** |
| **`not (n + 0 != n)`** | **`sat`** | `unsat` | ❌ **false-SAT** |

**패턴**: 양변이 **구문적으로 동일하면** 닫히고, 산술 정규화가 필요한 순간
네이티브 경로가 원자를 해석하지 않습니다 — **등식이면 "만족 가능"으로 결론
(틀린 판정)**, 부등식이면 abstain.

**가설 위치는 정상입니다**:

| | native |
|---|---|
| `assume h: n + 0 = n` / `goal: true` | `unsat` |
| `assume h: n + 0 = n` / `goal: n = n` | `unsat` |
| `assume h: z = n + 1` / `goal: z > n` | **`unsat`** ← 합에 이름을 붙이면 닫힘 |

마지막 줄이 진단을 확정합니다: **합을 등식으로 이름 붙여 가설에 두면 닫히고,
같은 산술이 goal 원자 안에 있으면 안 닫힙니다.** 그리고 §2의 결함 A도 "가설
쪽은 정상, goal 쪽만 어긋난다"였습니다 — **같은 goals-쪽 영역일 가능성**을
검토해 보실 만합니다.

## 심각도

- **방향은 verus-SAFE**입니다(false-SAT ⇒ "검증 실패"로 보고될 뿐 거짓 증명 아님).
- 그러나 **가장 단순한 산술에서 나오는 틀린 판정**이고, 위임을 끄는 순간 드러나므로
  기존 v2 원장에서는 전혀 보이지 않았습니다.
- 무엇보다 — **거의 모든 Verus goal 원자에 산술이 들어 있습니다.**

# 4. 그래서 §3의 답: 세 선택지 중 어느 것도 아닙니다

멈출 재생성이 없고(§1), A는 저희 경로를 안 지나며(§2), **실제 블로커는 §3입니다.**

지금 상태로 재생성을 돌리면 원장이 §3발 `unknown`/`sat`으로 뒤덮이고, 그쪽이
원하신 **귀속 표가 거의 전 행 "engine"으로 읽혀 아무것도 못 가릅니다.** 어제
요청문의 표현을 그대로 쓰면 — "어디서 왜 떨어지는지가 귀속되는 것"이 목적인데,
지금은 그 귀속이 한 덩어리로 뭉개집니다.

**권고 순서:**

| 순서 | 항목 | 이유 |
|---|---|---|
| **①** | **goal 원자 산술 정규화**(§3) | 이것부터 아니면 재생성이 측정으로서 무의미 |
| ② | 결함 A (`extra_hyps` → `hyps`) | 파급 좁음, 저희와 독립 |
| ③ | `rec` 표면 + elaborate 배선 (B) | 저희 emit의 재귀 커버리지 결정 |

①의 범위를 먼저 알려 주시면(전면 수정인지, 특정 원자 모양만인지) 저희가 emit
설계를 거기 맞추겠습니다. 예컨대 ①이 당장 어렵다면, 저희가 **goal 원자를 미리
평탄화해서**(모든 산술 부분항을 새 상수 + 정의 등식으로 뽑아 가설로 올리는)
emit할 수 있습니다 — 위 `z = n+1 ⊢ z > n` 이 닫히는 형태입니다. 다만 그건
"FOL 비계 0"이라는 이번 요청의 취지와 정면으로 어긋나므로, **①을 고치는 쪽을
권합니다.** 판단만 주시면 그대로 맞추겠습니다.

# 5. B(재귀 `fn`)에 대해

정직한 실패라는 진단, 그리고 `ADSMT_LUKB_DEBUG=1`로 **표면 실패**로 귀속하라는
지침 — 그대로 따르겠습니다. 확정하신 설계(`admit(rec f) ⟸ structural(f) ∨
proves_termination(f)`, 필수 modifier, 구조적 재귀는 `guard_ok`로 무증명 통과)도
저희가 리타겟 설계에서 도출한 요청과 일치합니다.

한 가지 보태면 — 저희 코퍼스의 재귀 64행 중 **48행이 `sum_to` 형태**입니다.
말씀하신 대로 `n - 1`은 구조적 부분항이 아니므로 전부 **종료-증명 갈래**로
갑니다. Verus는 이미 그 `decreases`를 별도 obligation으로 증명하고 있으므로,
그 side condition을 **추가 goal로 방출**하는 방식(그쪽 `elab_fn` 6단계가 반환
refinement 계약을 내는 것과 같은 모양)이면 커널 변경 없이 닿을 것으로 봅니다.
채택 여부만 알려 주시면 emit을 거기 맞추겠습니다. 거절하셔도 됩니다 — 그러면
48행을 영구 제외하고 분모를 정직하게 적겠습니다.
