# 0. 결함

```
fn Add(x0: Int, x1: Int): Int
const `a!`: Int
axiom: `a!` = 1
axiom: Add(`a!`, `a!`) = `a!` + `a!`
goal:  Add(`a!`, `a!`) = 2
```

네이티브가 **`sat`** — 즉 "반례를 찾았다" — 를 냈습니다. z3와 cvc5는 둘 다
`unsat`(목표 유효)입니다.

**이건 그쪽 인코딩의 중심 모양입니다.** Verus는 모든 산술을 `Add`/`Mul`/
`EucDiv` 같은 UF 래퍼 뒤에 두고 정의 공리로 푸는데, 그 정의 공리가 정확히
`UF응용 = 산술식` 형태입니다. 코퍼스 209행 전부에 들어 있습니다.

# 1. 왜 새어나갔나 — 백스톱 두 개가 **동시에** 꺼집니다

`LinArith::assert`의 복합 양성-등식 분기는 양쪽 모두 `linearize`되기를
요구합니다. `Add(a,a)`는 안 되므로 꼬리로 떨어지는데, 거기 있는
`is_multivar_arith`도 `arith_atom_arity`를 거치고 그것 **또한 양쪽을
요구**합니다. 그래서 `note_incomplete`가 안 불립니다.

두 번째 백스톱도 못 잡습니다. 폴라이트 결합은 버려진 원자가 **등식이 아닐
때만** `uninterpreted`를 세웁니다(`!is_eq_shaped` 가드). 이 원자는 등식입니다.

즉 진짜 산술 제약이 **백스톱 둘 다 꺼진 채로** 버려지고 `Sat`이 보고됩니다.
코드 주석이 근거를 적어놨는데 — "비산술 모양 `(= (f x) 5)`는 순수 UF 리터럴로
남기는 게 건전하다" — 그건 **반대편이 상수일 때만** 참입니다. 반대편이 변수를
가진 산술식이면 합동이 `+`를 계산할 수 없으므로 거짓입니다.

저희 규율 문서(`feedback_soundness_opaque_fallback`, "제약을 버리는 폴백은
절대 sat/unsat을 보고하면 안 된다")의 **4번째 재발이고, 네이티브 경로에서는
처음**입니다. 앞의 셋(rc.27/28/29)은 전부 위임 측이었습니다.

# 2. 방향과 영향

`sat`은 저희 의미론에서 **반례**이므로, 그쪽에는 **거짓 증명이 아니라 거짓
경보**로 나타납니다 — 유효한 의무가 "반례 있음"으로 보고되는 쪽입니다. 검증
결과를 잘못 통과시키는 방향이 아니니 그 점은 안심하셔도 됩니다.

다만 **어제 부탁드린 측정에는 직접 영향이 있습니다.** `ADSMT_NO_DELEGATION=1`
로 네이티브 단독을 재실 때, 이 수정 이전 바이너리는 이런 행에서 `sat`을
낼 수 있었습니다. **수정 이후 바이너리로 측정해 주십시오.**

# 3. 비용 — 없습니다

```
네이티브 209행 스윕:  92 unsat / 117 unknown — 행-단위 동일 (변화 0)
코퍼스 게이트:        173 verified, 회귀 0, 음성 컨트롤 8/8 (직전과 판정 동일)
```

백스톱을 켜는 변경은 판정을 `unknown` 쪽으로만 움직일 수 있는데, 아무 행도
움직이지 않았습니다.

# 4. 대신 나온 것 — **"벽"의 성격이 바뀝니다**

판정은 그대로인데 abstain **사유**가 크게 재배치됐습니다:

| 사유 | 이전 | 이후 |
|---|---|---|
| 이론 원자 미해석 | 58 | 47 |
| LIA: 산술 등식 표현 불가 | 0 | **70** |
| DPLL(T) 정제 한계 | **56** | **1** |
| 수량자 미도달 | 3 | 3 |

**"정제 한계에 걸린 56행"은 상당 부분 증상이었습니다.** 그 행들은 산술 등식을
조용히 버린 뒤 한참 아래에서 다른 이유로 실패하고 있었고, 이제 진짜 원인
지점에서 abstain합니다.

그쪽에 이 얘기를 드리는 이유는, 저희가 그동안 "네이티브가 못 닫는 이유"로
공유해 온 분류가 이 지점에서 바뀌기 때문입니다. 네이티브 abstain 사유를
기준으로 무언가 판단하고 계셨다면 새 표를 쓰셔야 합니다.

# 5. 요약

- **재핀**: AD1 `d4c4acc`. 원장 **173 불변**, 회귀 0.
- **측정**: `ADSMT_NO_DELEGATION=1` 스윕은 **이 커밋 이후 바이너리로**.
- **방향**: 거짓 경보 쪽이므로 그쪽 검증 통과 판정에는 위험 없음.
- **분류 변경**: 네이티브 abstain 사유 표가 바뀌었습니다(§4).
